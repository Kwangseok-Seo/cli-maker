# 요청 본문은 Param 이 아니라 Command 의 선택적 필드다

요청 본문을 `in: body` 인 **Param** 이 아니라 **Command** 의 포인터 필드 `body:` 로 표현한다 — 본문은 이름 붙은 여러 입력 중 하나가 아니라 명령당 최대 하나뿐인 페이로드이고, `nil` 이라야 "이 명령은 본문을 받지 않는다"를 표현해 본문 flag 를 그 명령에만 등록할 수 있기 때문에, 모든 입력을 `Param` 하나로 다루던 단일성을 잃고 실행기·생성 템플릿·공개 별칭이 각각 `Body` 를 따로 알아야 하는 비용을 감수한다.

거부한 대안: **`in: body` 인 Param** 은 OpenAPI 가 Swagger 2.0 에서 실제로 썼다가 3.0 에서 `requestBody` 라는 별도 필드로 옮긴 방식이다. petstore 2.0 spec 의 body param 7개는 `name` 이 전부 문자 그대로 `"body"` 인데, 이름이 할 일이 없다는 증상이 스키마에 그대로 남아 있다 — 게다가 "최대 하나"라는 제약을 리스트로는 표현할 수 없어 문서로만 강제된다. **값 struct `Body`** 는 `body:` 를 안 적은 명령과 `body: {}` 를 적은 명령이 파싱 후 둘 다 zero value 라 구별되지 않아, 본문을 받지 않는 GET 명령에까지 본문 flag 를 달게 만든다. `Auth` 가 값 struct 로 괜찮은 것은 `Auth.Type == ""` 이 sentinel 노릇을 하기 때문이지 값 struct 라서가 아니다 — Body 에는 그 자리에 놓을 필드가 없다.

`Validate` 에는 body 관련 규칙을 넣지 않는다. GET 에 본문을 붙이는 것은 RFC 9110 이 *의미*를 정의하지 않을 뿐 금지가 아니고 실제로 쓰는 API 가 있으며, ADR-0007 상 검증 실패는 그 매니페스트 **파일 통째**를 날리므로 실재하는 API 를 표현 못 하게 만드는 대가가 크다. 본문 없는 POST·PUT 도 흔해서 메서드만으로 본문 필요 여부를 판정할 수 없다. `contentType` 의 기본값도 `Validate` 가 채우지 않는다 — 검증기가 값을 변형하면 놀랍고, 기본값은 런타임 경로와 생성 경로가 **공유하는 한 함수**가 정해야 두 벌로 갈리지 않는다(ADR-0009 의 `AddSharedFlags` 와 같은 수법).
