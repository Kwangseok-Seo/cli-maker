# 출력 포맷의 기본값은 stdout 이 터미널인지로 정한다

`--output` 을 주지 않으면 stdout 이 터미널일 때만 JSON 을 들여쓰고 파이프·리다이렉트면 받은 바이트를 그대로 낸다 — 사람이 읽을 때의 편의와 `| jq`·`> repo.json` 의 바이트 보존을 **기본값 하나로** 동시에 얻기 위해, 같은 명령의 출력이 실행 맥락에 따라 달라지는 것을 감수한다(출력을 고정해야 하는 스크립트는 `-o raw` 처럼 명시해야 한다).

**포맷 실패를 실패로 취급하지 않는 것**이 이 결정을 성립시킨다. 자동으로 고른 pretty 가 JSON 아닌 응답에서 죽으면 자동 전환 자체가 위험해지므로, `rewrite` 는 `json.Indent`/`json.Compact` 가 거절한 본문을 **원본 그대로** 내보내고 종료 코드를 건드리지 않는다 — 평문을 주는 정상 엔드포인트(`GET /zen`)가 있기 때문이다. 되돌리기가 안전한 것은 두 함수가 실패 시 대상 버퍼를 원래 길이로 되돌리기 때문이고(측정: 앞부분이 유효한 `{"ok":1} <html>…` 에서도 0 바이트), 그래서 부분 출력이 새어 나간 뒤 원본이 또 나가는 이중 출력이 없다. 경고는 유저가 `-o pretty|compact` 를 **명시했을 때만** stderr 로 낸다 — 우리가 알아서 고른 포맷이 실패한 것은 유저가 요청한 적 없는 일이다. 이 침묵/경고의 갈림은 `Pretty`·`Compact` 의 `Warn` 필드가 채워졌는지로 표현된다.

**`encoding/json` 의 바이트→바이트 층만 쓴다**는 것도 이 결정에 묶인다. `Unmarshal` 로 `map[string]any` 를 거쳐 다시 `Marshal` 하면 map 에 순서가 없고 `Marshal` 이 키를 정렬하므로 서버가 보낸 필드 순서가 사라진다(측정: `id, node_id, name…` → `allow_forking, archive_url…`). 우리는 응답 스키마를 모르고 알 필요도 없으므로 값으로 파싱하지 않는다 — [ADR-0002](0002-manifest-collections-as-ordered-lists.md) 가 매니페스트 쪽에서 지킨 순서 보존을 응답 쪽에서도 지킨다.

거부한 대안: **항상 raw** 는 사람이 볼 때마다 `-o pretty` 를 쳐야 한다. **항상 pretty** 는 이미 문서화된 파이프 계약([ADR-0005](0005-http-error-surface.md))을 바꾸고 기본 경로가 늘 파싱을 타게 만든다. **`--pretty`/`--compact` bool 두 개**는 둘 다 켰을 때의 규칙을 따로 정해야 하고 포맷이 늘 때마다 플래그가 하나씩 는다 — 하나의 축 위에 값으로 두면 표면이 안 늘어난다. 터미널 판정은 `isTerminal` 이 `os.ModeCharDevice` 비트로 한다(실측: 콘솔 `Dcrw-rw-rw-` / 파이프 `prw-rw-rw-` / 리다이렉트 `-rw-rw-rw-`) — 표준 라이브러리만으로 Windows 에서 갈린다. 네 포맷을 실제 응답으로 대조한 출력은 [M7 로그](../learn/milestones/M7.md).
