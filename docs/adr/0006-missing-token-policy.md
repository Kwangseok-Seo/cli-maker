# 토큰이 없으면 경고만 남기고 인증 없이 보낸다

매니페스트에 `auth` 가 선언됐는데 그것이 가리키는 환경변수가 없거나 비어 있으면, **stderr 에 경고를 남기고 인증 헤더 없이 요청을 그대로 보낸다** — 익명으로도 200 이 나오는 엔드포인트를 auth 선언 하나 때문에 막지 않기 위해, 인증이 필요한 호출은 서버의 401 을 받고 나서야 실패한다는 지연을 감수한다.

**빈 값을 "없음"으로 취급하는 것**이 이 결정의 구조적 축이다. 측정해 보면 인증이 선택적인 엔드포인트에서 헤더를 안 붙이면 200 이지만 빈/엉터리 Bearer 를 붙이면 401 이다 — 즉 **빈 토큰을 싣는 것은 안 싣는 것보다 엄격히 나쁘다**. 그래서 `applyAuth` 는 `os.LookupEnv` 의 존재 여부와 값의 빈 여부를 모두 보고, 둘 중 하나라도 걸리면 헤더를 만들지 않는다. 다만 진단 문구는 둘을 구별한다 — "설정 안 됨"과 "설정됐는데 빈 값"은 원인이 다르고(후자는 셸 확장 실패가 흔하다) 유저가 볼 곳이 다르다.

거부한 대안: **즉시 거부**(요청 전 종료)는 GitHub 처럼 한 API 안에 익명 허용 엔드포인트와 인증 필수 엔드포인트가 섞여 있을 때 전자까지 죽인다 — 매니페스트 하나가 두 세계를 다 담는 것이 정상이다. **조용히 생략**은 익명 성공 시 rate limit 열화를 아무도 모르게 하고, 401 이 나도 어느 환경변수를 설정해야 하는지 단서를 주지 않는다.

경고가 stderr 로 가므로 stdout 파이프(`| jq`)는 깨지지 않는다 — [ADR-0005](0005-http-error-surface.md) 가 세운 격벽과 같다. `auth` 블록이 아예 없는 매니페스트는 경고도 내지 않는다(유저가 인증을 선언하지 않았다). 우리가 모르는 `auth.type` 은 조용히 삼키지 않고 그 타입 이름을 실어 경고한다. 세 정책을 실제 응답으로 대조한 출력은 [M5 로그](../learn/milestones/M5.md).
