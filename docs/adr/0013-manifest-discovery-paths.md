# 매니페스트는 여러 디렉토리에서 찾고, 합집합으로 다루며, 가까운 쪽이 이긴다

매니페스트를 찾는 자리를 프로세스 cwd 의 `apis/` 와 유저 설정 디렉토리(`os.UserConfigDir` 아래의 `cli-maker/apis`) 둘로 늘리고, 앞쪽을 찾았다고 끝내지 않고 **모두 읽어 합친다** — 프로젝트에 `apis/` 를 만드는 순간 전역 매니페스트가 아무 말 없이 전부 사라지는 것이 유저에게 원인을 알아낼 수단이 없는 `exit 0` 짜리 실패이기 때문이며, 대신 매 실행마다 디렉토리를 하나 더 스캔하는 비용과 어느 파일이 로드됐는지가 여전히 명령줄에 드러나지 않는 것(ADR-0003 의 암묵적 발견)을 감수한다.

거부한 대안은 **override** — 첫 번째로 찾은 디렉토리 하나만 쓰는 것이다. `--timeout` > `CLI_MAKER_TIMEOUT` > 기본값 사슬(M5)이 그 형태라 같은 말을 쓰고 싶어지지만, 그것은 값이 **하나**일 때의 규칙이다. 매니페스트는 컬렉션이라 "어느 값이 이겼나"가 아니라 "무엇이 보이나"가 답이 되고, 실측하면 프로젝트에 `apis/` 를 만드는 순간 설정 디렉토리의 API 가 통째로 사라지면서 stderr 에는 한 줄도 남지 않는다. 프로젝트 격리가 필요한 자리는 나중에 `--manifest` 로 따로 주면 된다 — ADR-0003 이 그것을 "발견 override 로는 유효"하다고 이미 열어 두었다.

이름이 겹치면 **앞선 디렉토리(가까운 쪽)가 이기고, 가려진 쪽은 stderr 에 이유가 남는다.** 이 판정은 새로 짜지 않았다 — `LoadDirs` 가 같은 `root` 를 넘겨 가며 `LoadDir` 을 부르므로, 앞서 붙은 명령이 다음 차례의 `checkGlobal`·`reservedCommand` 에 그대로 보인다. ADR-0007 이 예약어를 상수 목록으로 두지 않고 root 에게 물어본 결과가 디렉토리 축까지 덮은 것이고, 그래서 `$PATH` 형 shadowing 이 이 도구에서는 조용하지 않다.

경로는 **둘로 시작한다.** 실행 파일 옆(`os.Executable`)과 환경변수 override 는 뺐다 — `go install` 이 바이너리를 놓는 자리 옆에 `apis/` 를 두는 것은 부자연스럽고, 실행 파일 옆이 실제로 필요해지는 것은 아카이브를 풀어 쓰는 바이너리 배포부터다. 경로 목록은 늘리기는 쉽고 줄이기는 유저가 쓰던 자리를 뺏는 일이라, 적은 쪽에서 출발한다.

*어디를 볼지*는 `main` 의 `apiDirs` 가 정하고 `internal/cli` 는 `[]string` 을 받아 순회만 한다. `os.UserConfigDir` 은 GOOS 마다 다른 환경변수를 보고(windows `%AppData%`, unix `$XDG_CONFIG_HOME`) darwin 에서는 `$HOME` 뒤에 `/Library/Application Support` 를 강제로 붙이므로, 환경을 조종해 이 함수를 흔드는 테스트는 OS 를 옮기는 순간 깨진다. 그 경계 덕분에 `LoadDirs` 는 환경 없이 `t.TempDir` 둘만으로 검증된다.

이 결정은 ADR-0003 이 *"M5(인증·설정)에서 정한다"* 며 남겨 둔 자리를 채운다. M5 에서는 다루지 않았다.
