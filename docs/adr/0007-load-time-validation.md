# 매니페스트는 등록 전에 검증하고, 문제가 있으면 그 파일을 통째로 건너뛴다

매니페스트는 cobra 명령으로 등록되기 **전에** 검증하고, 문제가 하나라도 있으면 그 파일의 모든 명령을 통째로 건너뛴다 — 깨진 매니페스트가 CLI 전체를 죽이거나(한 command 안의 중복 param 이름은 실제로 `pflag` 패닉이었고 무관한 `greet` 까지 함께 죽였다) 조용히 다른 API 를 삼키는 것을 막기 위해, 그 파일의 **멀쩡한 명령까지 함께 사라지는 것**을 감수한다. M3 이 문법 오류에 세운 격벽을 의미 검증까지 넓힌 것이다.

검증이 **두 층**으로 갈리는 것이 이 결정의 구조적 축이다. `manifest.Validate` 는 매니페스트 하나만 보면 판정 가능한 것(빈 이름, 중복, `in`·method 화이트리스트, path 자리표시자 대응)을 맡고, `internal/cli` 의 `checkGlobal` 은 CLI 전역 표면을 알아야 판정 가능한 것(매니페스트 이름 충돌, 예약된 flag 이름)을 맡는다. 이 분할은 취향이 아니라 강제다 — 예약어 목록의 출처는 cobra 명령에 등록된 persistent flag 이고, `internal/manifest` 가 그걸 알려면 `internal/cli` 를 임포트해야 하는데 그쪽이 이미 `manifest` 를 임포트하고 있어 **순환 의존**이 된다. (사실 정정, M10: 위층이 통째로 런타임 전용인 것은 아니다. 매니페스트 이름 충돌과 그룹 persistent flag 는 이 CLI 의 전역 표면에 관한 것이라 생성물과 무관하지만, **명령 자신에게 붙는 flag** — 본문 flag — 와의 충돌은 생성된 CLI 에도 그대로 있다. 그래서 그 부분만 `CheckBodyFlags` 로 떼어 `generate` 도 부른다. 두 층 분할과 순환 의존 회피는 그대로 유효하므로 supersede 가 아니다.)

전역 검사는 예약어를 상수로 두지 않고 **CLI 자신에게 직접 묻는다** — 매니페스트 이름은 `root.Commands()` 에, 예약된 flag 이름은 그 매니페스트로 지은 그룹의 `PersistentFlags().Lookup` 에. 명령이나 flag 가 늘어도 목록이 저절로 따라오고, 먼저 등록된 매니페스트도 `root` 의 자식이므로 매니페스트끼리의 충돌이 같은 검사에 함께 걸린다. 같은 이유로 `Validate` 의 자리표시자 검사는 `BuildURL` 과 **같은 `strings.ReplaceAll` 연산**을 쓴다 — 검증을 따로 구현하면 언젠가 실행기와 다른 판정을 내린다.

거부한 대안: **부분 등록**(문제 있는 command 만 빼고 나머지를 등록)은 CLI 표면이 매니페스트와 조용히 어긋나게 만든다 — 유저는 자기가 적은 명령이 왜 없는지 모른 채 나머지를 쓰게 된다. **실행 시점 검증**은 이미 그렇게 동작하고 있었고, 그 결과가 `panic`·`/repos//cobra` 같은 엉뚱한 요청·exit 0 짜리 조용한 유실이었다. **경고 후 진행**은 인증 토큰 부재([ADR-0006](0006-missing-token-policy.md))와 달리 여기선 성립하지 않는다 — 토큰 없는 요청은 서버가 판정해 주지만, 깨진 매니페스트는 물어볼 상대가 없다.

이름 충돌 시 **먼저 등록된 쪽이 이긴다**(`os.ReadDir` 이 파일 이름순이라 결정론적). 승자가 파일 이름에 달린 것은 임의적이지만, 밀린 파일이 stderr 에 이름과 함께 보고되므로 조용하지 않다. 검증이 잡는 문제와 각각의 이전 동작은 [M6 로그](../learn/milestones/M6.md).
