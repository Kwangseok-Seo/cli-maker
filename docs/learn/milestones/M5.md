# M5 — 인증과 설정

> 로드맵: M5 · 선행: [[M4]]

## 한 일

매니페스트의 `auth` 블록이 드디어 일을 한다. 그리고 M4 가 코드에 박아 둔 30초 타임아웃을 **세 층의 설정**으로 꺼냈다. **M5 완료.**

- **5a — 토큰을 읽어 헤더로.** `executor.applyAuth` 가 `auth.env` 가 가리키는 환경변수를 `os.LookupEnv` 로 읽어 `Authorization: Bearer <토큰>` 을 단다. `Execute` 는 `out, errOut` 두 Writer 를 받고, `internal/cli` 가 `cmd.OutOrStdout()` / `cmd.ErrOrStderr()` 를 넘긴다.
- **5b — 토큰이 없을 때의 정책.** 세 정책을 GitHub API 로 실물 대조해 **경고 후 인증 없이 진행**으로 확정([ADR-0006](../../adr/0006-missing-token-policy.md)).
- **5c — 설정 우선순위.** `cli.resolveTimeout` 이 `--timeout` → `CLI_MAKER_TIMEOUT` → `defaultTimeout` 순으로 판정한다.

인증 검증에는 GitHub API 를 새 매니페스트(`apis/github.yaml`)로 붙였다. 한 API 안에 **인증 필수**(`/user`)와 **익명 허용**(`/repos/{owner}/{repo}`) 엔드포인트가 같이 있어서 정책의 비용이 그대로 드러나기 때문. petstore 는 공개 API 라 인증을 보여줄 수 없다.

## 실측 표 — 인증

| 실행 | stderr | stdout | exit |
|---|---|---|---|
| `gh whoami` (토큰 없음) | `warning: GITHUB_TOKEN is not set` + `Error: HTTP 401` | `Requires authentication` | 1 |
| `gh whoami` (빈 값) | `warning: GITHUB_TOKEN is set but empty` + `Error: HTTP 401` | `Requires authentication` | 1 |
| `gh whoami` (엉터리 토큰) | `Error: HTTP 401` | **`Bad credentials`** | 1 |
| `gh repo` (토큰 없음) | `warning: …is not set` | 저장소 JSON | **0** |
| `gh repo` (엉터리 토큰) | `Error: HTTP 401` | `Bad credentials` | 1 |
| `auth.type: apikey` | `warning: unknown auth type "apikey"` | 응답 JSON | 0 |
| auth 블록 없음 | — | 응답 JSON | 0 |
| `2>/dev/null` | — | JSON 만 깨끗이 | 0 |

읽는 법 셋:

- **`Requires authentication` ↔ `Bad credentials`** — 같은 401 인데 서버 문장이 갈린다. 헤더가 실렸다는 걸 서버가 증명해 준다. 우리 코드를 들여다볼 필요가 없었다.
- **`gh repo` 가 exit 0** — ADR-0006 이 값을 하는 지점. "즉시 거부" 정책이었다면 이 명령은 죽었다.
- **익명 200 ↔ 엉터리 토큰 401** — 그래서 빈 토큰은 **안 싣는 게** 맞다. 싣는 게 안 싣는 것보다 나쁘다.

## 실측 표 — 타임아웃 우선순위

| 실행 | 결과 |
|---|---|
| 기본 | 200, exit 0 |
| `--timeout 5s` | 200, exit 0 |
| `CLI_MAKER_TIMEOUT=1ns` | `Error: … context deadline exceeded`, exit 1 |
| **`CLI_MAKER_TIMEOUT=1ns` + `--timeout 30s`** | **200, exit 0** ← flag 승 |
| `CLI_MAKER_TIMEOUT=60` (단위 없음) | `Error: CLI_MAKER_TIMEOUT: time: missing unit in duration "60"`, 요청 안 나감 |
| `--timeout abc` | pflag 가 `RunE` 이전에 거절, exit 1 |

`1ns` 는 기다리지 않고 타임아웃을 확인하는 트릭이다. 네 번째 줄이 이 마일스톤의 핵심 — `Changed` 없이 `GetDuration` 만 봤다면 세 번째와 네 번째가 똑같이 동작한다.

## 대표 함정

- **진단이 다른 API 를 가리켰다.** 경고 문구에 `GITHUB_TOKEN` 을 상수로 박아 petstore 를 돌려도 `GITHUB_TOKEN` 이 나왔다. 이름은 이미 `Auth.Env` 로 받고 있었다 — CONTEXT.md 가 정의한 **Executor**("모든 매니페스트가 공유하는 단 하나의 실행기")가 문자열 하나로 깨진 셈. 30분 뒤 **거울상**을 또 밟았다: env 파싱 에러엔 이름을 *아예 안* 실어서 `time: missing unit...` 만으로는 flag 인지 env 인지 알 수 없었다([[error-wrapping]]).
- **에러 감싸기가 엉뚱한 층에 들어갔다.** `fmt.Errorf(...)` 를 flag 층에 넣자 `--timeout 5s` 를 정상적으로 친 사람까지 항상 실패했다 — `err` 가 `nil` 이어도 `fmt.Errorf` 는 에러 값을 만든다. 컴파일러가 `declared and not used: duration` 으로 먼저 잡았다. **미사용 변수 에러를 `_` 로 덮었다면 살아남았을 버그**다.
- **에러를 반환하면서 출력까지 했다.** `parse: …` 와 `Error: …` 가 같은 말을 두 번 했다. 반환이 곧 보고고, 출력 여부는 호출자가 정한다.
- **`default` 가 원인을 잘못 짚었다.** `auth.type: apikey` 를 만나 걸린 갈래인데 "wrong token" 이라고 말했다 — 토큰은 읽어 보지도 않은 자리. 고칠 곳은 매니페스트의 `type:` 줄이다.
- **개행을 안 붙였다.** 경고와 응답 본문이 달라붙었다(`...request{"id":10`).
- **내 배선 실수** — `build.go` 에서 `30*time.Second` 를 걷어내고 `time` import 를 안 지워 `imported and not used` 로 빌드를 깼다. M4 에서 같은 걸 밟고도 반복했다.

## 결정

- [ADR-0006](../../adr/0006-missing-token-policy.md) — **토큰이 없으면 경고만 남기고 인증 없이 보낸다.** 익명 허용 엔드포인트를 auth 선언 하나로 막지 않기 위해. 빈 값을 "없음"으로 취급하는 게 구조적 축 — 실측상 빈 토큰을 싣는 건 안 싣는 것보다 엄격히 나쁘다.
- **설정 우선순위 flag > env > 기본값은 ADR 아님.** offer-gate 의 "맥락 없이 의외" 를 통과하지 못한다 — 보편 관례라 미래의 독자가 "왜 이렇게 했지?" 라고 묻지 않는다.
- **env 파싱 실패는 에러로 거절.** flag 층(pflag)이 이미 그렇게 하므로 대칭. 국소·가역이라 ADR 아님.
- `apis/example.yaml` 의 `auth` 블록 제거 — petstore 의 pet 조회는 실제로 익명이라, M2 때 스케치로 넣은 `type: bearer` 가 이제 매 호출마다 헛경고를 냈다. auth 예시는 `apis/github.yaml` 이 맡는다.

## 남긴 후속 과제

- **`--timeout` 이 예약어가 됐다 (실측).** 매니페스트 param 이름이 `timeout` 이면 로컬 flag 가 루트의 persistent 를 가려, `Changed` 는 `true` 인데 `GetDuration` 이 `trying to get duration value of flag of type string` 을 낸다. CLI 전체가 죽지는 않고 그 명령만 exit 1 — M4 의 중복 param 패닉보다는 낫다. **M4 가 남긴 두 항목(`in:` 오타 무시, 중복 param 이름 패닉)과 한 묶음**이다: 셋 다 "등록 전에 매니페스트를 검사한다"가 처방.
- **`auth.type` 은 `bearer` 하나뿐.** `apikey`(헤더/쿼리), `basic` 은 경고만 내고 지나간다. 스키마를 `type: header, name: X-API-Key` 처럼 일반화할지, 타입을 열거로 늘릴지는 미정 — 매니페스트 스키마는 유저 계약이라 실물 비교가 필요한 자리.
- **토큰이 로그에 샐 자리.** 지금은 헤더를 어디에도 찍지 않지만, 나중에 `--verbose` 로 요청을 덤프하면 `Authorization` 을 가려야 한다.
- **M4 잔여 항목 그대로**: required 아닌 path param, 응답 개행, `--help` 에 필수 표시, `main.go` 스캔 루프를 `internal/cli` 로 옮기기.
