# M11 — OpenAPI 임포트

> 커밋: `02329a4 feat: import OpenAPI specs into manifests (M11)` · 로드맵: M11 · 선행: [[M10]] · 결정: [ADR-0011](../../adr/0011-importer-reads-five-places-directly.md), [ADR-0012](../../adr/0012-import-output-is-a-deterministic-draft.md)

## 한 일

M10 까지 매니페스트는 **손으로만** 쓸 수 있었다. M11 이 남의 명세(OpenAPI Spec)를 읽어 매니페스트를 만들어 낸다.

```
$ cli-maker import petstore.json --out apis/pstore.yaml --base-url https://petstore3.swagger.io/api/v3
cli-maker: securityScheme [api_key petstore_auth] 를 옮기지 않았다 — auth 는 손으로 적어야 한다
cli-maker: deletePet: param "api_key" 를 뺐다 — in "header" 는 지원하지 않는다
생성: apis/pstore.yaml (명령 19개)

$ cli-maker pstore getPetById --petId 1 -o compact
{"id":1,"name":"Pet1","photoUrls":[…],"tags":[],"status":"available"}
```

petstore 3.0.4 의 **19 operation 전부**가 넘어온다. 재컴파일은 없다 — 산출물이 매니페스트이고, 런타임은 그걸 읽던 그대로 읽는다([ADR-0001](../../adr/0001-runtime-interpreter-architecture.md)).

## 사다리 — 층마다 도구 하나

| 단계 | 대상 | 새로 익힌 것 |
|---|---|---|
| 11a | `Spec` struct + `Operations()` 결정론적 순회 | [[partial-decoding]], [[maps]] 의 무순서·`slices.Sorted(maps.Keys(…))` |
| 11b | `Op` → `manifest.Command` | 에러와 경고를 **다른 반환값**으로, [[identifier-shadowing]] ③ |
| 11c | `Spec` → `manifest.Manifest` 조립 | 버전 게이트, [[config-precedence]] 를 `--base-url` 에 재사용 |
| 11d | `import` 명령 + 파일 출력 | [[serialization]] 의 마샬 방향, `omitempty` 의 두 요구 |
| 11e | 테스트 · ADR · 위키 | 명령 생성자로 빼서 테스트 가능하게, mutation 으로 확인 |

## 결정 셋

**순서 — 저자 순서를 버렸다.** `paths` 는 map 이라 순서가 없다. ADR-0002 가 컬렉션을 리스트로 둔 근거 하나로 *"`--help` 순서를 유저가 적은 대로 보존"* 을 들었기에, **그 근거가 임포터까지 덮는지**를 물었다. 답은 아니오였다 — 거기서 말한 "유저가 적은 순서"는 손으로 쓴 매니페스트의 것이고, 외부 Spec 의 저자 순서까지 지키려면 `yaml.Node` 로 문서를 직접 걸어야 해서 비용이 이익을 넘는다. 사전순으로 갔고, ADR-0002 는 그대로 유효하다(→ [ADR-0012](../../adr/0012-import-output-is-a-deterministic-draft.md)).

**스킵 — required 여부로 갈랐다.** 못 옮기는 param 이 optional 이면 그것만 빼고 명령을 살리고, required 면 operation 을 통째로 뺀다. *필수 입력을 잃은 명령은 반드시 잘못된 요청을 보내지만, 선택 입력을 잃은 명령은 나머지가 정확하다.* petstore 에서 걸리는 것은 `deletePet` 의 `api_key`(optional header) 하나라 19/19 가 살았다.

**파싱 — 라이브러리를 안 썼다.** 우리가 읽는 자리가 다섯이고, petstore 의 `$ref` 43개는 전부 `requestBody`/`responses` 안 — 우리가 보는 자리엔 0개다(→ [ADR-0011](../../adr/0011-importer-reads-five-places-directly.md)).

## 겪은 함정

- **Swagger 2.0 이 경고 없이 절반 통과했다.** 2.0 은 `paths`·`operationId`·`in: path` 를 3.0 과 같은 이름으로 써서, [[partial-decoding]] 이 그대로 받아들인다. `servers` 가 없어 baseUrl 이 비고 param 타입이 `type: ""` 로 유실되는데 **경고 0건**이었다. 부분 디코드는 "이 문서가 내가 아는 형식인가"를 물어봐 주지 않는다 → 버전 게이트를 손으로 세웠다.

- **테스트가 통과했는데 메시지가 틀린 말을 했다.** 버전 게이트의 첫 문구는 `swagger "2.0" 값이 잘 못 되었다` 였다. 테스트는 *"에러에 `2.0` 이 들어 있나"* 만 봤고 `%q` 가 값을 찍으면서 우연히 만족됐다. 그런데 `"2.0"` 은 **틀린 값이 아니라 정확히 맞는 Swagger 2.0 값**이라, 이 문장을 본 유저는 고칠 게 없는 스펙을 고치러 간다. 테스트는 *문자열의 존재*를 못 박을 수 있어도 *문장이 쓸모 있는지*는 못 박는다 → 찍어 봐야 하는 층이 남는다.

- **공허하게 통과하는 테스트를 썼다.** `TestConvertRejectsUnknownVersion` 의 fixture 를 `paths: {}` 로 뒀더니, 버전 게이트가 스텁인 채로도 통과했다 — `manifest.Validate` 가 *"Command 가 비어 있다"* 로 먼저 걸렀기 때문이다. **거절할 구실이 하나만 남게** fixture 에 멀쩡한 operation 을 넣어 고쳤다.

- **테스트 기대값을 확인 없이 썼다.** `findPetsByStatus.status` 를 "optional query param" 이라 단정했는데 스펙엔 `required: true` 였다. 코드가 맞고 기대값이 틀린 경우. 진짜 optional 인 `loginUser` 케이스를 따로 추가했다.

- **불가능한 분기를 방어했다.** `if op.Path == ""` 을 뒀는데 `methods()` 가 `Path` 를 안 채우므로 늘 참이었다. 조건을 뒤집어 보니 19개 전부 `Path` 가 비어 실패 — 거짓 가지가 죽은 길임이 드러났다. 동작이 아니라 **읽는 사람에게 거짓말을 하는 것**이 문제였다(*"methods() 가 Path 를 채울 때도 있구나"*).

## 되짚어 본 것

**정책을 상수로 꺼냈다.** `checkVersion` 안에 `"3."` 이 리터럴로 있었고, 같은 함수의 에러 문구에도 `3.x` 가 따로 박혀 있었다. 지원 범위를 넓힐 때 판정만 고치고 문구는 옛 범위를 계속 광고하는 드리프트다. `supportedMajor` 하나로 묶고 `"4."` 로 바꿔 보니 판정과 문구가 함께 움직였다.

이 repo 의 기존 결도 같았다 — `allowedMethods`/`allowedParamIn`(정책은 이름 붙은 데이터) + `Validate`/`SupportsParamIn`(함수 이름은 질문). 그래서 `checkVersion3` 로 이름을 바꾸는 대신 상수를 뺐다.

**목록을 복제하지 않았다.** 임포터가 *"이 `in` 을 옮길 수 있나"* 를 알아야 했는데, `path`/`query` 를 여기 적는 대신 `manifest.SupportsParamIn` 을 냈다. 실행기가 header 를 지원하게 되는 날 임포터만 조용히 뒤처지는 것을 막는다.

## 남긴 것

- `in: header` param 은 여전히 못 옮긴다. 실행기가 지원하면 `SupportsParamIn` 이 자동으로 따라온다.
- `securitySchemes` → `auth` 매핑 없음. oauth2·apiKey 어느 쪽도 `{type: bearer, env}` 에 안 맞는다.
- `components.parameters` 재사용을 쓰는 spec 은 아직 못 만났다. 만나면 `$ref` 가 우리가 보는 자리에 처음 들어오므로 ADR-0011 을 재검토한다.
