# M6 — 매니페스트 검증

> 로드맵: M6 (M5 이후 로드맵에 삽입 — 출력 포맷은 M7 로 밀림) · 선행: [[M5]]

## 한 일

M3~M5 가 하나씩 남겨 온 "깨진 매니페스트" 과제를 한 번에 정리했다. 매니페스트는 이제 **cobra 명령으로 등록되기 전에** 검증을 통과해야 하고, 통과 못 하면 그 파일만 통째로 빠진다. **M6 완료.**

먼저 **재고 조사부터** 했다. 알려진 문제는 둘뿐이었고 나머지는 추측이었기 때문에, 깨진 매니페스트 9종을 만들어 지금 실제로 무슨 일이 벌어지는지 측정했다. 그 결과가 검증 목록을 정했다.

- **6a — 국소 검증** (`manifest.Validate`): 매니페스트 하나만 보면 판정 가능한 것.
- **6b — 전역 검증** (`internal/cli` 의 `checkGlobal`): CLI 전역 표면을 알아야 판정 가능한 것. 이때 M4·M5 가 계속 미뤄 온 *"`main.go` 의 스캔 루프를 `internal/cli` 로"* 가 `cli.LoadDir` 로 해결됐다. `main.go` 는 세 줄로 줄었다.

## 측정 — 검증 전에는 무슨 일이 일어났나

| 매니페스트 문제 | 이전 | 지금 |
|---|---|---|
| 한 command 에 중복 param 이름 | **`panic: ping flag redefined: a`, exit 2 — 무관한 `greet` 까지 사망** | 생략 + `param "a" 가 중복이다` |
| 매니페스트 `name` 충돌 | `--help` 에 같은 이름 두 번. 가려진 쪽은 **help 를 stdout 에 뱉고 exit 0** | 생략 + `이미 쓰이고 있는 명령 이름이다` |
| `name: greet` (내장 명령과 충돌) | 내장이 이겨서 `greet zen` 이 "안녕, zen!" | 같음 |
| `name: help` / `completion` | 매니페스트가 이겨서 **내장 도움말·자동완성이 사라짐** | 같음 |
| param 이름이 `help` | `--help` 가 `flag needs an argument` 로 깨지고, `"help" flag declared as non-bool. Please correct your code` | 생략 + `예약된 flag 이름이다` |
| param 이름이 `timeout` | `Changed` 는 true 인데 `GetDuration` 이 타입 에러 | 같음 |
| 중복 command 이름 | exit 0, 두 번째 command 도달 불가 | 생략 + `이름이 중복이다` |
| `in: quiery` (오타) | exit 0, flag 는 생기는데 요청엔 안 실림 | 생략 + `in "quiery" 는 지원하지 않는다` |
| `in: header` (미구현) | exit 0, 조용히 무시 | 생략 + 지원하지 않는다고 명시 |
| 빈 command/param 이름 | exit 0 | 생략 + 인덱스로 위치 지목 |
| path 자리표시자에 param 없음 | 빈 문자열이 치환돼 `/repos//cobra` 가 **실제로 나감** → 404 | 생략 + path 원본을 실어 보고 |
| path param 이 `required` 아님 | 유저가 안 주면 같은 문제 | 생략 + `required 여야 한다` |
| `method: "GET TT"` | 실행 시점에 `invalid method` | 로드 시점에 생략 |
| `baseUrl` 없음 | 실행 시점에 `unsupported protocol scheme ""` | 로드 시점에 생략 |

**가장 위험한 것은 패닉이 아니라 exit 0 이었다.** 패닉은 요란해서 유저가 알아차리지만, 매니페스트 이름 충돌은 아무 소리 없이 다른 API 를 통째로 삼키고 성공으로 끝났다.

## 실측 — 한 매니페스트에 문제가 넷일 때

```
$ cli-maker greet 철수
cli-maker: apis\_probe.yaml 생략
baseURL "GET TT": scheme 이 http/https 가 아니다
commands[0]: name 이 비어 있다
commands[1] "ping": method "get" 는 지원하지 않는다
commands[2] "ping": 이름이 중복이다
안녕, 철수!                                 ← 격벽 유지, exit 0
```

`errors.Join` 이 넷을 한 번에 보고한다. 하나씩 알려주면 유저는 매니페스트를 고치러 네 번 왕복한다.

## 대표 함정

- **`seen` 의 선언 위치가 규칙의 범위다.** command 이름 집합은 함수당 하나(매니페스트 전체에서 유일), param 이름 집합은 command 마다 새로(그 command 안에서만 유일). 루프 안에서 누적자를 만들면 아무것도 기억 못 하는데 — M4 의 `q := url.Values{}` 와 같은 모양 — 여기선 **일부러 안쪽에서** 만든다. "누적 구간이 어디까지인가"를 먼저 정해야 위치가 나온다.
- **`errors.New` 는 포맷팅을 안 한다.** `errors.New(("...%d", i, name))` 은 두 겹으로 틀렸다 — Go 에는 괄호로 묶은 인자 목록이라는 문법이 없고(`expected ')', found ','`), `New` 는 문자열 하나만 받는다. 값을 끼워 넣으려면 `fmt.Errorf`.
- **에러 문자열 끝의 `\n`.** `errors.Join` 이 이미 개행으로 잇기 때문에 빈 줄이 하나씩 낀다. Go 에서 에러 문자열을 소문자로 시작하고 문장부호 없이 끝내는 관례가 이런 합성 때문이다.
- **순환 의존이 설계를 강제했다.** 예약된 flag 이름 검사를 `manifest` 에 두려면 `cli` 를 임포트해야 하는데 그쪽이 이미 `manifest` 를 임포트한다. Go 가 컴파일 에러로 막아서, 검증이 국소/전역 두 층으로 갈렸다 — 취향이 아니라 강제.
- **진짜 매니페스트가 쓰레기 파일에 밀렸다 (실측).** `_probe.yaml` 이 `github.yaml` 보다 파일 이름순으로 앞이라 먼저 등록됐고, 진짜 GitHub 매니페스트가 생략됐다. `os.ReadDir` 이 정렬해 주니 결정론적이긴 하지만 승자가 파일 이름에 달려 있다.

## 결정

- [ADR-0007](../../adr/0007-load-time-validation.md) — **등록 전 검증, 문제 있으면 그 파일 통째로 생략.** 부분 등록(문제 있는 command 만 빼기)을 거부한 이유는 CLI 표면이 매니페스트와 조용히 어긋나기 때문. 검증이 국소/전역 두 층으로 갈리는 것과, 전역 검사가 예약어를 상수로 두지 않고 `root` 에 직접 묻는 것이 구조적 축.
- **`method: get` (소문자)은 거부한다.** 대문자로 조용히 고쳐 주는 안도 있었지만, 매니페스트를 몰래 고치기 시작하면 유저가 쓴 것과 도는 것이 갈린다. 국소·가역이라 ADR 아님.
- **이름 충돌 시 먼저 등록된 쪽이 이긴다.** 양쪽 다 거부하는 안과 비교했는데, 지금은 밀린 파일이 stderr 에 보고되므로 조용하지 않다는 점이 결정적이었다.

## 남긴 후속 과제

- **충돌 메시지가 누가 이름을 가져갔는지 말하지 못한다.** `root.Commands()` 는 명령이 어느 파일에서 왔는지 기억하지 않는다. 매니페스트 출처를 들고 다니면 `name "gh" 는 apis/_probe.yaml 이 이미 쓰고 있다` 가 된다.
- **생략 메시지에 들여쓰기가 없다.** 매니페스트 둘이 동시에 깨지면 어느 파일의 문제인지 줄들이 섞인다.
- **`in: header`·`body` 는 거부만 하고 구현은 없다.** `auth.type` 이 `bearer` 하나뿐인 것과 같은 자리 — 매니페스트 스키마를 넓힐 때 함께 다룬다.
- **검증에 테스트가 없다.** 지금은 깨진 YAML 을 손으로 떨어뜨려 확인한다. table-driven test 의 교과서적 대상이라 M8 의 첫 과제.
- **M4·M5 잔여**: 응답 개행, `--help` 에 필수 표시.
