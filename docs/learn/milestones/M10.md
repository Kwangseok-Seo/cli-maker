# M10 — 요청 본문 (request body)

> 커밋: `2785023 feat: send request bodies with --data (M10)` · 로드맵: M10 · 선행: [[M9]]

## 한 일

M9 까지 cli-maker 는 **본문을 보낼 수 없었다.** 정확히는 막혀 있지 않고, *보낸다고 광고하면서 빈 본문을 보냈다.*

```
$ cli-maker pstore --help
Available Commands:
  addPet      POST /pet          ← 검증 통과, --help 에 노출

$ cli-maker pstore addPet
Error: HTTP 400 Bad Request                    exit 1
{"code":400,"message":"Input error: The input body …  (약 20KB 의 Java 객체 덤프)
```

세 곳이 겹쳐 있었다 — `allowedMethods` 는 `POST`·`PUT`·`PATCH` 를 **허용**하고, `allowedParamIn` 은 body 를 **적을 수조차 없게** 하고, `Execute` 는 본문 자리에 `nil` 을 **박아** 두고 있었다. 요란하게 실패하긴 했지만 이유는 서버 말로만 나왔다.

M10 이 그 셋을 닫았다. **M10 완료.**

```
$ cli-maker echo post --data '{"from":"runtime"}'
{"body":"{\"from\":\"runtime\"}","contentLength":18,"contentType":"application/json",…}

$ echo '{"from":"stdin"}' | cli-maker echo post --data -      # stdin
$ cli-maker echo post --data @pet.json                        # 파일
$ cli-maker echo post                                         # required
Error: required flag(s) "data" not set                        exit 1, 요청은 안 나간다
$ cli-maker echo get --id 1 --data x                          # 본문 안 받는 명령
Error: unknown flag: --data                                   exit 1
```

## 원래 순서를 바꿨다

세션은 **OpenAPI 임포트**로 시작했다. petstore 3.0 을 재 보니 19 operation 중 **7개가 `requestBody`** 였다 — 임포터를 먼저 만들면 37% 를 버린 채 내고 곧바로 다시 손대야 했다. 그래서 body 를 M10 으로 당기고 임포터를 M11 로 미뤘다.

> 처음 낸 선택지는 "임포터만 / 임포터+body" 둘뿐이었는데, **재고 나서** 세 번째(순서 바꾸기)가 보였다. 측정이 선택지 목록 자체를 바꾼 경우다 → [[M9]] 의 같은 교훈.

## 사다리 — 층마다 도구 하나

| 단계 | 대상 | 새로 익힌 것 |
|---|---|---|

| 10c | `--data` 세 입력원 | [[cobra]] 의 `Changed`, `cmd.InOrStdin()` |

## 결정 — OpenAPI 가 이미 겪고 입장을 바꿨다

body 를 `in: body` 인 **Param** 으로 둘지 **Command** 의 필드로 둘지가 첫 갈림길이었다. 설명으로 고르지 않고 spec 두 벌을 실제로 받아 봤다.

| | Swagger 2.0 | OpenAPI 3.0 |
|---|---|---|
| 표현 | `parameters: [{in: body, name: "body"}]` | `requestBody:` **별도 필드** |
| petstore 에서 | body param 7개, `name` 이 **전부** 문자 그대로 `"body"` | `parameters` 없음, `requestBody` 만 |

`name` 이 항상 `"body"` 인 것이 증상이다 — 이름이 할 일이 없다. "최대 하나"라는 제약도 리스트로는 표현되지 않아 문서로만 강제된다. **OpenAPI 자신이 2.0 → 3.0 에서 옮겨간 길을 우리가 되밟을 이유가 없었다** → [ADR-0010](../../adr/0010-request-body-as-command-field.md).

`CONTEXT.md` 의 Param 정의는 그때까지 *"query/path/body/header 중 어디에 실리는지"* 였다 — 도메인 언어가 **2.0 쪽에 서 있었다.** 함께 정정했다.

## 측정 — 인터페이스가 같아도 구체 타입이 전송을 바꾼다

`httptest` 로 서버를 띄워 **서버가 받은 것**으로 판정했다. payload 는 14바이트.

| Execute 에 넘긴 것 | 서버가 본 ContentLength | Transfer-Encoding |
|---|---:|---|
| `strings.NewReader(payload)` | 14 | — |
| `io.NopCloser(strings.NewReader(payload))` | **-1** | **chunked** |

내용은 글자 하나 안 다르고 둘 다 `io.Reader` 다. `http.NewRequest` 가 안에서 구체 타입을 확인하기 때문이다([[interfaces]] 의 타입 단언이 표준 라이브러리 안에서 쓰이는 자리). chunked 면 `GetBody` 도 안 심겨 **리다이렉트 재전송이 조용히 실패**한다.

이 측정이 10c 의 설계를 정했다 — `--data` 는 어느 입력원이든 **다 읽어서** 감싼다. 추측이 아니라 위 표가 근거다.

## 같은 문제가 세 층에 나왔다

"안 줬다"와 "빈 것을 줬다"를 가르는 문제가 M10 안에서 세 번 반복됐다 → [[absent-vs-empty]].

| 층 | 표식 |
|---|---|
| YAML → struct (`body:` 없음 vs `body: {}`) | **포인터** `*Body` 가 `nil` |
| flag (`--data` 없음 vs `--data ""`) | **`Changed()`** |
| HTTP (본문 없음 vs 길이 0 본문) | **`Content-Type` 유무** |

1층을 포인터로 푼 **직후** 2층에서 `raw == ""` 로 판정하는 코드를 썼다. mutation 으로 되돌려 보고서야 같은 문제였음이 드러났다.

## 새 충돌 자리 — 가드와 검사는 쌍이다

`-o`·`--timeout` 은 그룹의 persistent flag 라 같은 이름의 param 이 **가리기만** 했다. `--data` 는 명령 자신에게 붙어서 **pflag 를 패닉시킨다.** 양쪽을 각각 지워 보면:

| 지운 것 | 결과 |
|---|---|
| `Build` 의 중복 등록 가드 | `panic: withBody flag redefined: data` — 보고할 기회조차 없다(`Build` 가 `checkGlobal` 보다 먼저 돈다) |
| `checkGlobal` 의 충돌 검사 | 패닉은 없는데 **유저가 적은 query param 이 exit 0 으로 증발** |

둘 다 있어야 "그 파일만 빠지고 이유를 말한다"가 된다. 조용한 쪽이 더 나쁘다 → [[M6]].

예약 이름을 `"data"` 상수로 적지 않고 **등록 함수에게 물어봤다** — 빈 명령에 같은 `Body` 로 달아 보고 무엇이 붙는지 본다. 부수 효과로 `Body` 가 nil 인 명령은 같은 param 이름을 써도 걸리지 않는다. 상수 목록이었다면 없는 문제를 보고했을 것이다.

## pinning — mutant 여섯

| 어긋낸 곳 | 잡은 것 |
|---|---|
| `Body` → `body` (소문자) | **컴파일러** (`has no field or method Body`) |
| `*Body` → `Body` (값) | **컴파일러** (`mismatched types Body and untyped nil`) |
| `yaml:"body"` → `yaml:"requestBody"` | **테스트** — `Body = nil, body: 를 적었는데 안 채워졌다` |
| `Changed()` → 값이 비었는지로 판정 | 테스트 — `--data ""` 케이스 |
| 리터럴을 `io.NopCloser` 로 감쌈 (**내용 동일**) | 테스트 — `리더 타입 = io.nopCloserWriterTo` |
| 템플릿이 `ContentType` 을 빠뜨림 | `TestSurfaceMatchesRuntime` **PASS**, `TestGeneratedCarriesBody` FAIL |

앞의 둘은 테스트가 아니라 **컴파일러**가 잡았다. **타입에 관한 결정은 컴파일러가 지키고, 태그는 문자열이라 컴파일러가 못 본다** — 테스트가 진짜 필요한 자리는 세 번째다. `load_test.go` 의 원래 주석이 이미 그렇게 적어 두고 있었다: *"yaml 태그가 실제로 먹었는가"*.

마지막 줄은 새 테스트가 자기 값을 증명한 자리다. `ContentType` 은 flag 표면에 나타나지 않아 M9 의 골든 테스트가 덮지 못한다 — 명령 수도 flag 수도 그대로고 요청의 `Content-Type` 만 조용히 바뀐다.

## `generate` 의 구멍 — ADR-0007 의 전제가 깨졌다

ADR-0007 은 검증을 두 층(매니페스트 국소 / CLI 전역)으로 갈랐고, `generate` 는 전역 층을 *"이 CLI 의 표면에 관한 것이라 생성물과 무관"* 하다며 건너뛰었다. M10 에서 그 전제가 깨졌다 — 본문 flag 충돌은 **생성된 CLI 에도 그대로 있다.**

```
# 닫기 전
$ cli-maker generate clash.yaml
… sub.Flags().String("data", "", "query - string")     ← 실행하면 패닉할 소스, exit 0

# 닫은 뒤
Error: commands[0] "withBody": param "data" 는 본문 flag 이름과 겹친다     exit 1
```

`CheckBodyFlags` 로 그 부분만 떼어 두 경로가 함께 부른다. 결정 자체(두 층 분할·순환 의존 회피)는 유효하므로 supersede 가 아니라 **사실 정정** — [[M9]] 에서 같은 ADR 의 다른 절을 정정했던 것과 같은 처리다.

## 두 CLI 를 나란히 돌렸다

같은 매니페스트로 런타임 경로와 생성 경로를 모두 실행했다(생성물은 `go build` 로 진짜 바이너리를 만들어서).

| 호출 | 런타임 | 생성물 |
|---|---|---|
| `post --data '{…}'` | `application/json` | `application/json` |
| `form --data 'a=1'` | `application/x-www-form-urlencoded` | `application/x-www-form-urlencoded` |
| `post` (required 누락) | `required flag(s) "data" not set` | 같음 |
| `get --id 3 --data x` | `unknown flag: --data` | 같음 |

`--data` 의 도움말 문구를 템플릿에 다시 적지 않았기 때문이다 — 생성된 소스는 `clirun.AddBodyFlag(sub, c.Body)` 한 줄을 부를 뿐이다([[M9]] 의 `AddSharedFlags` 와 같은 수법).

골든 테스트도 같은 규율을 따른다. 생성물에서 `AddBodyFlag` 호출을 보면 flag 이름·usage 를 테스트가 다시 적는 대신 **소스에서 읽어 낸 `Body` 로 그 함수를 실제로 불러** 무엇이 붙는지 본다 → [[go-ast]].

## 대표 함정

- **표적이 고장나 있었다.** `--data` 가 다 됐는데 petstore 가 500 을 줬다. PowerShell 로 직접 POST 해도 같은 500 이라 서버 쪽 문제로 갈렸다 — 우리 코드를 고치러 들어갔다면 헛돌았을 것이다. 로컬 echo 서버로 표적을 옮겨 결정적으로 만들었다.
- **측정 장치가 종료 코드를 덮어썼다.** 패닉 mutant 를 잴 때 `| Select-Object -First 6` 파이프가 `$LASTEXITCODE` 를 0 으로 바꿔 놓았다. 종료 코드를 인용하지 않고 넘어갔다 — [[M9]] 에서 `go run` 의 stderr 를 프로그램 출력으로 오독했던 것과 같은 부류.
- **한 층을 풀고 다음 층에서 같은 문제를 못 알아봤다** (위 "세 층" 절).
- **선례를 이유 없이 따를 뻔했다.** `Auth` 가 값 struct 라서 `Body` 도 값으로 두려 했는데, `Auth` 가 괜찮았던 건 `Auth.Type == ""` 이 sentinel 이기 때문이었다. **선례가 성립한 이유**를 봐야 했다.

## 남긴 후속 과제

- ~~**`Execute` 의 파라미터가 8개다.**~~ → **닫혔다** (아래 잔여 정리).
- ~~**`parse` 가 `Body` 를 주소로 찍는다**~~ (`Body:0x3eeb9d5f4408`). `%+v` 는 중첩 포인터를 안 펼친다 → [[pointers]]. → **닫혔다** (아래).
- **`main.go` 의 `generate` → `CheckBodyFlags` 배선은 테스트가 없다.** `package main` 은 임포트할 수 없다. 함수 자체는 `TestCheckBodyFlags` 가 덮고, 배선은 수동 실측(exit 1)이 전부다 — [[M9]] 가 남긴 것과 같은 한계.
- **stdin 의 개행을 지우지 않는다.** `echo … | --data -` 는 `\r\n` 을 포함한 18바이트를 보낸다. curl 의 `--data` 는 지우고 `--data-binary` 는 안 지우는데 우리는 후자다. 지우는 쪽은 payload 를 조용히 바꾸므로 안 지우는 것으로 정했다.
- **`header` param 은 여전히 미지원.** petstore 에 1개 있다(`deletePet` 의 `api_key`, optional). M11 임포터가 이걸 만난다.
- **본문 검증이 없다.** `--data '{'` 같은 깨진 JSON 도 그대로 나간다. 서버가 판정해 주므로 ADR-0006 의 논리(물어볼 상대가 있으면 보낸다)를 따른다.

## M10 이후 — 잔여 정리

새 기능 없이 M10 이 남긴 둘만 닫았다.

**1. `Execute` 의 파라미터 8개를 `Call` struct 로 묶었다** (8 → 5).

묶은 근거는 개수가 아니라 **짝**이다 — `Values` 는 `Command.Params` 를, `Body` 는 `Command.Body` 를 유저 입력으로 채운 것이라 `Command` 없이는 뜻이 없다. 그리고 위치 인자로 늘어놓으면 nil 을 받을 수 있는 자리가 **나란히** 붙는다:

```go
Execute(ctx, m, c, nil, nil, format.Raw{}, &out, &errOut)   // 이전 — 두 nil 이 뒤바뀌어도 컴파일된다
Execute(ctx, Call{Manifest: m, Command: c}, format.Raw{}, &out, &errOut)   // 이후
```

시작할 때 "시그니처가 `clirun` 을 통해 외부 계약"이라고 적었는데 **틀렸다.** 공개 표면은 `clirun.Run(cmd, m, c)` 이고 `executor` 는 `internal/` 이라 밖에서 볼 수 없다 → [[internal-packages]]. 위험도를 잘못 매겼던 것이고, 확인하고 나니 자유롭게 고칠 수 있었다.

**테스트를 한 줄도 안 고치고 통과했다** — 호출 형태만 바뀌고 동작은 그대로라는 뜻이다.

**2. `parse` 를 `%+v` 대신 YAML 로 낸다.**

```
이전:  … Params:[] Body:0x3eeb9d5f4408}]}
이후:  commands:
           - name: post
             method: POST
             path: /things
             params: []
             body:
               required: true
               contentType: ""
           - name: get
             …
             body: null
```

`omitempty` 는 쓰지 않았다. 디버그 도구에서는 **"이 자리가 비었다"가 곧 답일 때가 많아서**다 — `baseUrl` 오타를 쫓을 때 그 줄이 사라지면 안 된다. `body: null` 이 명시적으로 보이는 것도 같은 이유다.

부수 효과로 출력이 **입력과 같은 언어**가 됐다. 매니페스트를 나란히 놓고 "내가 적은 것"과 "cli-maker 가 이해한 것"을 직접 대조할 수 있다.
