# M4 — 제네릭 HTTP 실행기

> 로드맵: M4 · 선행: [[M3]]

## 한 일

매니페스트가 **진짜 API 호출**이 됐다. M3 까지는 보낼 요청을 화면에 적기만 했는데, 이제 `internal/executor` 가 그걸 실제로 보내고 응답을 흘려보낸다. **M4 완료.**

두 조각으로 나눠 진행했다.

- **4a — URL 조립.** `executor.BuildURL(m, c, values)` 가 Param 값으로 `{petId}` 를 치환하고 쿼리를 붙인다. `internal/cli` 는 `c.Params` 를 돌며 flag 를 등록하고, `Run` 에서 값을 걷어 `map[string]string` 으로 넘긴다. ADR-0002 가 예고한 *"조회가 필요해지는 시점에 리스트에서 map 을 파생한다"* 가 여기서 실현됐다.
- **4b — 전송.** `executor.Execute(ctx, m, c, values, out)` 가 `NewRequestWithContext` → `Do` → `io.Copy` 를 잇는다. `Run` 은 `RunE` 가 되어 에러를 종료 코드까지 올린다.

```
$ cli-maker petstore getPetById --petId 10
{"id":10,"name":"Rufus","photoUrls":["example.com"],"tags":[]}

$ cli-maker petstore getPetById --petId abc
{"code":400,"message":"Input error: couldn't convert `abc` to type `class java.lang.Long`"}
Error: HTTP 400 Bad Request          ← stderr
[exit 1]
```

## 실측 표

| 입력 | stdout | stderr | exit |
|---|---|---|---|
| `getPetById --petId 10` | 펫 JSON | — | 0 |
| `findByStatus --status available` | 목록 JSON | — | 0 |
| `findByStatus` | 목록 JSON (`?` 안 붙음) | — | 0 |
| `getPetById --petId abc` | 400 본문 | `Error: HTTP 400 Bad Request` | 1 |
| `getPetById` | — | `required flag(s) "petId" not set` + 사용법 | 1 |
| `findByStatus ... \| head -c 120` | 잘린 JSON | — (사용법 덤프 없음) | — |

인코딩도 확인했다 — 같은 값 `a b/c` 가 쿼리에선 `a+b%2Fc`, 경로에선 `a%20b%2Fc` 로 갈린다([[url-encoding]]).

## 대표 함정

- [[unused-results]]: **같은 실수를 두 번** 밟았다. `strings.ReplaceAll(...)` 의 반환값을 버려 치환이 없던 일이 됐고(`go vet` 도 조용), 나중에 `fmt.Errorf(...)` 를 `return` 없이 써서 400 이어도 exit 0 이 될 뻔했다(이번엔 `go vet` 이 잡음). 컴파일러·vet·테스트가 각각 다른 층을 막는다는 감각을 얻었다.
- [[defer]]: `defer resp.Body.Close()` 를 `err` 검사보다 위에 두면 `resp` 가 `nil` 이라 패닉한다. 실측에서 **패닉 지점이 함수 끝이 아니라 `defer` 를 쓴 그 줄**이었다 — 수신자는 `defer` 시점에 평가되기 때문. 진짜 손해는 크래시가 아니라 `connectex: 연결 거부` 라는 정확한 진단이 `invalid memory address` 로 덮인 것.
- [[io-reader-writer]]: "흘려보낸다"를 보이려고 만든 데모가 `strings.Reader` 의 지름길(`WriterTo`) 때문에 한 번에 다 가버렸다. `resp.Body` 와 같은 성질의 소스로 다시 재서야 32KB × 4 를 봤다.
- [[cobra]]: `SilenceUsage` 를 명령에 박으면 `required flag` 안내까지 죽는다. `RunE` **안에서** 켜야 둘 다 산다.
- 루프 안에 `q := url.Values{}` 를 둬서 매 반복마다 누적자가 새로 태어났다.

## 결정

- **Param 의 CLI 표면 = 전부 flag** (path/query 구분 없이 `--name 값`). path 를 positional 로 두는 안과 실물 비교했는데, path param 이 2개일 때 `getRepo cobra spf13` 처럼 순서를 바꿔 써도 **에러 없이 잘못된 URL**(`/repos/cobra/spf13`)이 나왔다. flag 는 순서 무관이고 cobra 의 required 검증을 그대로 쓴다. 유저 계약이라 되돌리기 비싼 결정.
- **flag 타입은 전부 `String`** (`type: int` 이어도). `GetInt` 는 미지정을 `0` 으로 주어 `?count=0` 과 구별할 수 없다. `""` 를 "미지정"의 신호로 삼는 규칙이 `BuildURL` 전체를 지탱한다. 국소·가역이라 ADR 아님.
- **4xx/5xx → 본문은 stdout, 상태는 stderr, exit 1.** 세 정책을 실제 400 응답으로 대조해 골랐다. 본문이 stdout 인 건 세 안 공통이라 `| jq` 는 어느 쪽이든 안 깨지고, 갈리는 건 종료 코드와 진단뿐이었다. 본문이 빈 에러를 주는 API 에서 단서가 남는 쪽을 택했다.
- **타임아웃 30초, 코드에 상수로.** 설정화는 M5.

## 남긴 후속 과제

- **`in:` 이 조용히 무시된다.** `switch p.In` 에 `default` 가 없어 `header`·`body`(미구현)나 `quiery` 같은 오타가 아무 경고 없이 사라진다. M3 이 남긴 "의미 검증(명령 단위)" 과제와 같은 뿌리.
- **required 아닌 path param.** 유저가 안 주면 `{petId}` 가 그대로 남아 이상한 URL 이 나간다. path param 은 로드 시점에 required 를 강제하거나 조립 때 거부해야 한다.
- **중복 param 이름이 격벽을 뚫는다 (실측).** 한 Command 안에 같은 `name` 의 Param 이 둘 있으면 `pflag` 가 `panic: twice flag redefined: a` 로 죽는다. 이 패닉은 `cli.Build` 중 — 즉 **CLI 가 뜨는 도중** — 발생하므로 그 매니페스트와 무관한 `cli-maker greet 철수` 까지 함께 죽는다. M3 이 세운 격벽(깨진 매니페스트 하나만 건너뛰기)은 **문법 오류만** 막고 있었다. 등록 전에 이름 충돌을 검사해 그 매니페스트만 버려야 한다.
- **개행 없음.** 응답 본문이 개행으로 끝나지 않으면 프롬프트·`Error:` 줄이 본문에 달라붙는다(`...Long"}Error: HTTP 400`). raw 통과가 기본이라 curl 도 같지만, 터미널일 때만 개행을 붙이는 선택지가 있다 — 출력 포맷을 다루는 M6 의 자리.
- **`--help` 에 필수 표시.** `MarkFlagRequired` 는 도움말에 안 드러난다. 도움말 문자열에 직접 적어야 한다.
- `main.go` 의 스캔 루프를 `internal/cli` 로 옮기는 건 이번에도 보류 — M4 에서 `main.go` 는 손대지 않았다.
