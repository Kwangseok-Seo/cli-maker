# M8 — 테스트

> 커밋: (커밋 후 기록) · 로드맵: M8 · 선행: [[M7]]

## 한 일

일곱 마일스톤 동안 **테스트가 0개**였고, ADR 8건은 산문으로만 있었다. M8 은 그중 셋을 **실행 가능한 판정**으로 바꿨다. 테스트 함수 9개 / 서브테스트 37개, `go test ./...` 이 `exit 0`. **M8 완료.**

커버리지 숫자가 목표가 아니었다. 전역 규칙 `adr-rationale-realization`(쓴 것과 도는 것을 대조한다)을 **사람이 매번 눈으로 하지 않게 만드는 것**이 실질이었다.

## 사다리 — 층마다 도구 하나

| 단계 | 대상 | 새로 익힌 것 |
|---|---|---|
| 8a | `executor.BuildURL` | 익명 struct 테이블, `t.Run` 서브테스트 |
| 8b | `manifest.Validate` | 에러 **묶음** 판정 — `Unwrap() []error` 를 익명 인터페이스로 단언 |
| 8c | `format` · `cli/output` | `bytes.Buffer`+`strings.NewReader` 로 메모리 io, `t.Helper`/`t.Cleanup`/`t.TempDir` |
| 8d | `executor.Execute` | **`httptest`** — 진짜 서버, `http.HandlerFunc`, 클로저로 요청 붙잡기 |

순수 함수 → 에러 묶음 → 메모리 io → 네트워크. **네트워크는 마지막 층에서야 등장한다.**

## 측정 — 추측이 두 번 뒤집혔다

**① `NUL` 은 char device 였다.** M7 에서 "이 환경의 stdout 은 어떤 경로로도 TTY 가 아니다"를 실측했던 터라 `isTerminal` 의 참 분기는 못 잰다고 적으려 했다. 재 보니 아니었다:

```
os.DevNull = NUL
os.DevNull (쓰기)   mode=Dcrw-rw-rw-   ModeCharDevice=true    ← M7 의 콘솔과 같은 mode
os.Stdout          mode=-rw-rw-rw-    ModeCharDevice=false
임시 일반 파일        mode=-rw-rw-rw-    ModeCharDevice=false
```

콘솔의 **대리물이 유효한지를 먼저 재고** 썼다. `/dev/null` 도 char device 라 리눅스에서도 같다.

**② `0.30s` 는 타임아웃이 아니었다.**

```
execute_test.go:242: Execute 가 돌아오기까지 50.3496ms
--- PASS: TestExecuteHonorsContextTimeout (0.30s)
```

`Execute` 는 제때 끊었고, 나머지 250ms 는 `srv.Close()` 가 자고 있는 핸들러를 기다린 시간이다([[httptest]]).

## 대표 함정

- **건네려던 스켈레톤이 컴파일되지 않았다.** `m := ...` 를 선언하고 쓰는 자리를 `// TODO` 로 비워 `declared and not used: m`. M4 의 "쓰지 않는 import 로 사용자 빌드를 끊은" 것과 같은 종류이고, 이번엔 **건네기 전 `go vet` 이 잡았다.** 빈칸을 남긴 골격은 `_ = BuildURL(...)` 처럼 일단 쓰이게 해야 한다.
- **아무것도 단언하지 않는 테스트가 `ok` 로 통과했다.** `_ = BuildURL(...)` 상태의 통과는 "확인했다"가 아니라 "안 물어봤다"였다 — `silent-failure-first`(exit 0 인데 의도와 다른 것) 의 테스트판. 판정을 붙인 직후 **기대값을 일부러 틀리게 해 실패를 한 번 보는 것**을 루틴으로 삼았다.
- **기대값을 직관으로 적어 틀렸다.** query param 을 `zebra`, `apple` 순으로 선언했으니 URL 도 그 순서일 줄 알았지만 `?apple=2&zebra=1` 이다([[url-encoding]]). 그래서 테이블을 쓰기 **전에** 폐기용 probe 로 `BuildURL` 의 현재 출력 7가지를 먼저 쟀다. **코드가 옳은데 테스트가 틀리는** 실패는 원인이 더 멀다.
- **오타 하나가 에러 둘을 만든다.** `in: "quer"` 는 "모르는 in" + "치환할 param 이 없음" 둘로 보고된다. 개수까지 판정했더니 드러났고, 지금은 "유저에겐 둘 다 사실"이라 계약으로 뒀다 — 나중에 줄이려면 그 행이 깨지며 **결정을 강제**한다.
- **M7 의 배선이 여기서 값을 치렀다.** `os.Stdout` 대신 `cmd.OutOrStdout()`/`cmd.ErrOrStderr()` 를 쓴 덕에 테스트가 `cmd.SetOut(&buf)` 한 줄로 출력을 가로챈다. 직접 `os.Stdout` 을 썼다면 지금 이 테스트들은 못 썼다.

## 결정

전부 국소·가역이라 **ADR 게이트를 대 봤지만 통과한 것이 없다**(역전 비용 작음). 사유와 함께 여기 남긴다.

- **테스트는 같은 패키지에 둔다** (`package executor`, not `executor_test`). `applyAuth`·`isTerminal`·`rewrite`·`checkGlobal` 처럼 **밖에 안 내보낸 함수가 판단의 핵심**이라서. 되돌리려면 파일 상단 한 줄.
- **목을 만들지 않는다.** `httptest` 로 진짜 서버를 띄우고 `BaseURL` 만 바꾼다 — 프로덕션 코드 변경 0줄. `http.DefaultClient` 라는 전역을 쓰는데도 가능한 이유는 **목적지가 이미 데이터로 표현돼 있어서**다.
- **구조가 아니라 행동으로 판정한다.** `resolveFormatter` 의 반환 타입을 보는 대신 고른 포매터에 본문을 흘려 결과를 본다. 그래야 `Warn` 이 `cmd` 의 stderr 에 배선됐는지까지 걸린다. 예외는 auto+터미널 한 곳 — 출력이 `NUL` 로 사라져 행동을 볼 수 없어 타입을 확인했다.
- **콘솔 대리는 `os.DevNull`.** 대리가 유효한지(같은 `ModeCharDevice` 비트) 먼저 재고 썼다.

## 남긴 후속 과제

- **`cli/load.go` 가 안 덮였다.** `t.TempDir()` 에 깨진 yaml 을 써 넣고 **M3 격벽**(하나가 깨져도 나머지는 산다)과 `checkGlobal`(매니페스트끼리 이름 충돌)을 확인하는 것이 다음 자리. 커버리지 18.8% 의 대부분이 여기다.
- **`manifest/load.go`(YAML 읽기)도 비어 있다.** 깨진 YAML·없는 파일의 에러 표면.
- **`Build`(cobra 배선)는 end-to-end 로만 잡힌다.** `cmd.SetArgs([...])` + `Execute()` 로 루트부터 돌리는 테스트가 필요하다 — flag 필수 여부, `RunE` 의 에러 전파까지.
- **우리 에러에는 센티널이 없다.** 테스트가 메시지 조각에 의존하므로 문구를 다듬으면 깨진다. 기계가 분기에 쓸 일이 생기면 그때 센티널을 둔다([[error-wrapping]]).
- **M7 잔여**: shorthand 는 `Lookup` 이 안 본다 · 포맷은 stdout 만 탄다 · `Formatter` 는 NDJSON 을 모른다.
- **M4 잔여**: `--help` 에 필수 param 표시.
