# M9 — `generate` (코드 생성)

> 커밋: `41c7c35 feat: generate standalone CLI source from manifests (M9)` · 로드맵: M9 · 선행: [[M8]]

## 한 일

[ADR-0001](../../adr/0001-runtime-interpreter-architecture.md) 이 코드 생성을 **"당분간" 거부**하면서 남긴 문장이 있었다 — *"런타임 방식이 확정하는 도메인 모델은 코드 생성의 입력과 동일하므로, 뒤에 `generate` 서브커맨드로 **얹을** 수 있다."* M9 는 그 문장이 참인지 처음 밟아 본 마일스톤이다.

결과: 참이었다. 매니페스트 struct 를 그대로 템플릿에 먹였고, `executor` 는 한 줄도 고치지 않고 재사용했다. **M9 완료.**

```
$ cli-maker generate apis/github.yaml --dir out/gh     # main.go 95줄 + go.mod 2줄
$ cd out/gh && go mod edit -replace ... && go mod tidy && go build -o gh .
$ ./gh repo --owner spf13 --repo cobra -o compact
{"id":12574344,"node_id":"MDEwOlJlcG9zaXRvcnkxMjU3NDM0NA==",…      ← yaml 없이 돈다
```

## 결정 — 세 경로를 실제로 빌드해서 골랐다

"생성물이 독립 모듈이면 `internal/executor` 를 못 쓴다"는 벽을 어떻게 넘을지가 갈림길이었다. 설명으로 고르지 않고 셋을 다 만들어 빌드했다.

| | **A. 라이브러리 의존** | **B. 자립 생성** | **C. 모듈 안 생성** |
|---|---|---|---|
| 생성물 | `main.go` 15줄 + `go.mod` | `main.go` 31줄 + `go.mod` | repo 안의 `.go` 파일 |
| 빌드 산출물 | `gh.exe` 2,721,280 B | `gh.exe` 2,722,816 B | `cli-maker.exe` |
| 독립 배포 바이너리 | ✅ | ✅ | ❌ |
| executor 버그 고치면 | 재빌드만 (`[FIXED]` 전파됨) | **재생성 필수** (옛 복사본) | 재빌드만 |

크기가 거의 같은 것(1.5KB 차)이 핵심이다 — Go 는 정적 링크라 **A 도 실행 시 의존이 없다.** 차이는 *빌드할 때* cli-maker 가 필요한가이지 *실행할 때*가 아니다.

**A + 얇은 façade** 로 정했다. `internal/` 은 그대로 두고 생성물이 실제로 부르는 것만 공개한다 → [ADR-0009](../../adr/0009-generated-cli-shape.md).

두 번째 갈림길은 "생성물을 얼마나 펼칠 것인가"였고, **펼쳐서**(명령마다 cobra 블록)를 골랐다. 얇게 두면 9d 의 golden test 가 자명해져 무의미해지고, ADR-0001 이 코드 생성을 열 이유로 든 "명령별 커스텀 로직"의 씨앗이 안 생긴다.

## 측정 — `go.mod` 한 줄이 프로그램을 바꿨다

`go 1.26` 을 `go 1.21` 로만 바꾸고 코드는 한 글자도 안 건드렸다:

| 명령 | `go 1.26` | `go 1.21` |
|---|---|---|
| `gh whoami` | `{"message":"Requires authentication",…}` exit **1** | `Encourage flow.` exit **0** |
| `gh zen` | `Approachable is better than simple.` | `Encourage flow.` |

`gh whoami` 가 젠 명언을 반환한다 — 모든 서브커맨드가 매니페스트의 마지막 명령을 실행한다. Go 1.22 의 루프 변수 변경이 **모듈마다 이 줄로 켜고 꺼지기** 때문이다([[go-modules]] · [[closures]]).

exit 0 에 그럴듯한 응답이라 아무도 눈치채지 못한다. 그래서 생성기가 뱉는 `go` 줄을 자동 추론이 아니라 **눈에 보이는 상수**로 두고 1.22 하한을 테스트로 지킨다.

## 자물쇠가 잠기는지 — 돌연변이 넷

"펼쳐서"를 고른 대가는 `internal/cli.Build` 와 `main.go.tmpl` 의 **중복**이다. 9d 가 그걸 봉인한다. 통과하는 테스트는 실패할 수 있어야 하므로 일부러 어긋내 봤다:

| 어긋낸 곳 | 결과 |
|---|---|
| 템플릿의 Short 형식 | FAIL `생성물 "GET: /plain", 런타임 "GET /plain"` |
| 템플릿에서 `MarkFlagRequired` 삭제 | FAIL (Required 불일치) |
| **런타임**(`build.go`)의 Short 형식 | FAIL `생성물 "GET /plain", 런타임 "GET @ /plain"` |
| 템플릿 첫 줄 표식 | FAIL (상수와 갈림) |

**양방향으로 잡힌다.**

## 인용 — 조용한 쪽이 더 위험했다

`Validate` 는 param 이름의 문자를 제한하지 않는다. 즉 `say"hi` 도 생성기까지 온다.

| 입력 | 날것 `"{{.}}"` | `{{printf "%q" .}}` |
|---|---|---|
| `say"hi` | 컴파일 안 됨 | `"say\"hi"` 값 보존 |
| `C:\temp` | **유효한 Go 인데 값이 바뀜** (`\t`=탭) | `"C:\\temp"` 값 보존 |
| `two⏎lines` | 리터럴 미종료 | `"two\nlines"` 값 보존 |

가운데 줄이 위험하다 — 깨지는 쪽은 즉시 발견되지만 이건 조용하다. 그래서 **유저 문자열은 예외 없이 `%q` 를 거친다**([[text-template]]).

## 대표 함정

- **잘못된 전제로 질문했다.** "`repo-name` 을 어디서 막을까"를 3지선다로 물었는데, *"param 이름이 Go 식별자 자리에 간다"* 는 전제 자체가 **내 데모 템플릿의 선택**이었다. 명령마다 익명 블록 `{ ... }` 을 쓰면 식별자를 만들 필요가 없어 문제가 사라진다. 막는 자리보다 **왜 막는가**가 먼저였다 — "Go 식별자가 아니라서"로 적었다면 backend 가 바뀌는 날 근거가 썩는다.
- **측정 장치가 네 번 틀렸다.** ① 파이썬 `re.sub` 이 치환 문자열의 `\t` 를 탭으로 바꿔 템플릿이 이상한 값을 낸 것처럼 보였다. ② `go run` 이 stderr 에 덧붙이는 `exit status 1` 을 프로그램 출력으로 착각해 "두 경로가 다르다"고 오판했다(컴파일된 바이너리끼리 재니 동일). ③ GitHub `/zen` 이 호출마다 다른 문구를 줘서 본문 비교가 무의미했다. ④ `awk` 로 템플릿을 깨뜨리려다 엉뚱한 곳을 지웠다. 전부 **값이 예상과 다르면 대상보다 측정 장치를 먼저 의심**해서 걸렸다.
- **`replace` 를 쓰면 internal 을 부를 수 있을 줄 알았다.** 로컬 소스를 직접 가리켜도 막힌다 — 규칙은 "받을 수 있느냐"가 아니라 "부를 수 있느냐"다([[internal-packages]]).
- **생성물의 `go.mod` 에 `require` 를 적으려 했다.** cli-maker 는 아직 배포 전이라 어떤 버전을 적어도 거짓이 된다(`git ls-remote … exit status 128`). `go mod tidy` 에 맡기니 두 줄이면 충분했다.

## 남긴 후속 과제

- **cli-maker 가 배포되지 않아 생성물이 그대로 빌드되지 않는다.** 지금은 `go mod edit -replace` 안내를 stderr 로 낸다. 태그를 붙여 공개하면 이 안내가 사라진다.
- **생성물의 빌드를 아무도 자동으로 확인하지 않는다.** 9d 는 소스를 파싱할 뿐 `go build` 를 돌리지 않는다. 느리고 네트워크를 타서 뺐다 — CI 가 생기면 그쪽 자리다.
- ~~**`generate` 가 `-o`·`--timeout` 을 상속받는다.**~~ 루트의 persistent flag 라 `--help` 에 보이는데 생성에는 아무 영향이 없다. 무해하지만 표면이 거짓말을 한다. → **닫혔다** (아래 잔여 정리).
- **명령별 커스텀 로직은 여전히 표현할 수 없다.** A 는 ADR-0001 이 든 두 이유 중 *독립 배포 바이너리* 만 준다. 요구가 실제로 오면 템플릿을 두껍게 하는 방향(B)으로 얹는다.
- **`--help` 대조는 명령 목록만 같다.** 생성물은 루트라 `help`·`completion` 이 더 붙는다. 구조적 차이라 golden test 는 매니페스트에서 나온 명령만 본다.
- ~~**M8 잔여** 중 `cli/load.go`·`manifest/load.go` 테스트는 그대로 남아 있다.~~ → **닫혔다** ([[M8]] 의 후속 과제 절 · [[testing-the-filesystem]]).

## M9 이후 — 잔여 정리

새 기능 없이 M8·M9 가 남긴 것만 닫았다. 순서를 **테스트 먼저**로 잡았다 — 뒤의 flag 이전이 유저 계약을 건드리므로 안전망이 먼저 있어야 했다.

**1. 안 덮인 두 파일에 테스트를 붙였다** (18 케이스, 49 → 69). `t.TempDir()` 에 매니페스트를 써 넣는 방식([[testing-the-filesystem]]). 통과 여부만으로 만족하지 않고 `load.go` 를 한 군데씩 지워 **돌연변이 4종이 모두 잡히는지** 확인했다. 3번(`.yml`)을 고친 뒤 다시 재니 확장자 자물쇠가 **비어 있었다** — 그 케이스가 겸하던 역할이 사라졌기 때문이다. `zzz.txt` 케이스를 더해 채웠다.

**2. `-o`·`--timeout` 을 루트에서 API 그룹으로 내렸다.** 설명으로 고르지 않고 B 안을 실제로 빌드해 위치별로 쟀다.

| 호출 | 이전 | 이후 |
|---|---|---|
| `gh repo … -o compact` | exit 0 | exit 0 |
| `-o compact gh repo …` | exit 0 | **exit 0** |
| `-o compact greet 철수` | exit 0 (무영향) | exit 1 `unknown shorthand flag: 'o'` |
| `generate … -o compact` | exit 0 (무영향) | exit 1 |

3번째 줄이 예상과 달랐다 — 루트에서 flag 를 떼면 루트 앞자리 호출이 깨질 줄 알았는데 안 깨졌다. cobra 는 flag 를 **최종 대상 명령**의 flag 집합으로 파싱하기 때문이다([[cobra]]). 그래서 의미 있던 자리는 하나도 잃지 않고 무영향 자리만 거절하게 됐다. 67 테스트는 **한 줄도 안 고치고** 통과했다 — 테스트가 기제가 아니라 행동을 봤다는 뜻이다.

부수 효과: 생성된 CLI 는 이미 자기 루트(= API 그룹)에 이 둘을 달고 있어 두 경로가 *더* 대칭이 됐다.

**3. `.yml` 이 조용히 사라지던 것을 고쳤다.** 테스트를 쓰다 발견했다 — `LoadDir` 이 `.yaml` 만 봐서, `.yml` 로 저장한 매니페스트는 에러도 명령도 남기지 않았다. exit 0 에 아무 말이 없어 유저가 알아낼 방법이 없는 조용한 유실이다. 확장자가 둘이 되면서 생긴 새 자리(`a.yaml` 과 `a.yml` 이 같은 이름을 주장)는 **기존 이름 충돌 검사가 그대로 잡았다** — 특례를 두지 않았다.

**4. ADR-0007 의 한 절을 정정했다.** *"예약어 목록의 출처는 **루트에** 등록된 persistent flag"* 가 2번 때문에 거짓이 됐다. 결정 자체(두 층 분할·순환 의존 회피)는 그대로 유효하므로 supersede 가 아니라 사실 정정이다 — 출처를 "cobra 명령에 등록된" 으로 넓혀 다시 썩지 않게 했다. 덤으로 `clirun/timeout.go` 의 *"param 이 같은 이름을 쓰면 로컬 flag 가 이걸 가린다 (M5 후속 과제)"* 주석도 **이미 거짓**이었음이 드러났다 — M6 부터 등록 시점에 거부된다(실측: `param "timeout" 는 예약된 flag 이름이다`).

**5. 공유 flag 등록을 `clirun` 으로 접었다** — 태그를 붙이기 전에.

`clirun` 은 flag 를 읽기만 하고 등록은 호출자 둘(`internal/cli.Build`, 생성된 `main.go`)이 각자 했다. 그래서 기본값이 두 벌이었고, `resolveTimeout` 은 flag 가 안 주어지면 **등록된 기본값을 무시하고** `defaultTimeout` 을 쓴다 — 즉 등록 쪽 숫자는 표시용이다. 실측으로 갈라 보였다:

```
clirun 의 defaultTimeout 만 30s → 1ns (다른 파일 무수정)
  gh --help  →  --timeout duration  … (default 30s)     ← 거짓말
  gh zen     →  Error: context deadline exceeded        ← 실제로는 1ns
```

`clirun.AddSharedFlags(cmd)` 하나를 표면에 더하고 두 호출자가 그걸 부르게 했다. 같은 측정을 다시 하니 런타임 CLI 와 생성물 **양쪽 `--help` 가 `(default 1ns)`** 로 함께 움직였다. 표면은 7 → 8 개가 됐지만 복제는 3곳 → 1곳이다. 상수 넷(`DefaultTimeout`·`OutputAuto`·shorthand·usage)을 각각 내보내는 것보다 좁고, ADR-0009 의 "펼쳐서 낸다"는 그대로다 — 명령 블록은 손대지 않았다.

태그 **전에** 해야 했던 이유: 태그를 붙이면 생성된 CLI 들이 각자 `30*time.Second` 를 자기 소스에 복사해 갖는다. 나중에 고쳐도 이미 나간 것은 따라오지 않는다.

부수 수확으로 템플릿의 `time` import 가 필요 없어졌다 — 안 지웠으면 생성물이 `imported and not used` 로 컴파일되지 않는다(M4 에서 밟은 함정). 생성된 `main.go` 는 95 → 94줄.

**6. 패키지 doc 에 시그니처로 쓸 수 없는 것을 적었다.** 지원 소비자 범위(= `generate` 가 낸 코드, 손으로 조립하는 경로는 검증이 없어 비지원), cobra 유출이 의도적이라는 것, `v0.x` 의 의미. 여기서 `go doc` 이 **별칭의 필드를 안 펼친다**는 것이 드러났다([[go-doc]]) — `type Manifest = manifest.Manifest` 한 줄만 나온다. 원본이 `internal/` 이라 밖에서는 볼 수도 없으니, 필드 모양을 doc 에 적고 그 목록이 썩지 않게 `reflect`+`go/parser` 로 대조하는 테스트를 뒀다.

### 자물쇠 확인 (2·5·6)

| 지운 것 | 깨진 것 |
|---|---|
| `Build` 의 `AddSharedFlags` 호출 | `TestBuildRegistersSharedFlags` · `TestBuildEndToEnd` 4 · `TestLoadDir/param 이 예약된 flag…` |
| 템플릿의 `AddSharedFlags` 호출 | `TestGeneratedDelegatesSharedFlags` |
| (추가) `manifest.Param` 에 필드 하나 | `TestAliasFieldsAreDocumented` |

첫 줄의 `TestLoadDir/param…` 이 함께 깨진 것이 이 구조의 증거다 — `checkGlobal` 이 예약 flag 를 **그룹에게 묻기** 때문에, 그룹이 flag 를 잃으면 예약어 검사도 함께 죽는다. 상수 목록이었다면 조용히 통과했을 것이다.

`TestBuildEndToEnd` 는 M8 이 남긴 *"`Build` 는 end-to-end 로만 잡힌다"* 를 닫는다 — `cmd.SetArgs` + `Execute()` 로 루트부터 돌려 param flag 등록·필수 표시·공유 flag 상속·`clirun.Run`·실행기를 한 번에 밟는다. `httptest` 로 진짜 서버를 띄우고 **서버가 받은 경로·쿼리**로 판정한다.

### 대표 함정

- **돌연변이 스크립트가 대상을 오염시켰다.** 파이썬 `write_text` 가 `\n` → `\r\n` 으로 저장해, LF 로 정규화하는 repo 에서 `git status` 에 `M load.go` 가 남았다. 테스트는 전부 통과했으니 **테스트만 봤다면 못 봤다.**
- **선택지를 내기 전에 잰 것이 판단을 바꿨다.** "루트 앞자리 호출이 깨진다"를 대가로 적어 물어볼 참이었는데, 실제로 재 보니 깨지지 않았다. 안 쟀다면 없는 대가를 근거로 결정을 요청했을 것이다.
