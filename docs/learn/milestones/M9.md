# M9 — `generate` (코드 생성)

> 커밋: `41c7c35 feat: generate standalone CLI source from manifests (M9)` · 로드맵: M9 · 선행: [[M8]]

## 한 일

[ADR-0001](../../adr/0001-runtime-interpreter-architecture.md) 이 코드 생성을 **"당분간" 거부**하면서 남긴 문장이 있었다 — *"런타임 방식이 확정하는 도메인 모델은 코드 생성의 입력과 동일하므로, 뒤에 `generate` 서브커맨드로 **얹을** 수 있다."* M9 는 그 문장이 참인지 처음 밟아 본 마일스톤이다.

결과: 참이었다. 매니페스트 struct 를 그대로 템플릿에 먹였고, `executor` 는 한 줄도 고치지 않고 재사용했다. **M9 완료.**

```
$ cli-maker generate apis/github.yaml --dir out/gh     # main.go 95줄 + go.mod 2줄
$ cd out/gh && go mod edit -replace ... && go mod tidy && go build -o gh .
$ ./gh repo --owner spf13 --repo cobra -o compact
{"id":12574344,"node_id":"MDEwOlJlcG9zaXRvcnkxMjU3NDM0NA==",…      ← yaml 없이 돈다
```

## 사다리 — 층마다 도구 하나

| 단계 | 대상 | 새로 익힌 것 |
|---|---|---|
| 9a | `clirun/` façade | [[type-aliases]], [[internal-packages]] — 실행 본체를 두 경로가 공유 |
| 9b | `generate` + 첫 템플릿 | [[text-template]], [[go-embed]] |
| 9c | 검산 + `go.mod` 생성 | `go/format.Source`([[go-ast]]), 덮어쓰기 가드 |
| 9d | golden test | `go/parser`·`ast.Inspect`([[go-ast]]) |

façade → 생성 → 검산 → 자물쇠. **먼저 두 경로가 공유할 것을 정하고**, 그 다음에 갈라지는 것을 만들었다.

## 결정 — 세 경로를 실제로 빌드해서 골랐다

"생성물이 독립 모듈이면 `internal/executor` 를 못 쓴다"는 벽을 어떻게 넘을지가 갈림길이었다. 설명으로 고르지 않고 셋을 다 만들어 빌드했다.

| | **A. 라이브러리 의존** | **B. 자립 생성** | **C. 모듈 안 생성** |
|---|---|---|---|
| 생성물 | `main.go` 15줄 + `go.mod` | `main.go` 31줄 + `go.mod` | repo 안의 `.go` 파일 |
| 빌드 산출물 | `gh.exe` 2,721,280 B | `gh.exe` 2,722,816 B | `cli-maker.exe` |
| 독립 배포 바이너리 | ✅ | ✅ | ❌ |
| executor 버그 고치면 | 재빌드만 (`[FIXED]` 전파됨) | **재생성 필수** (옛 복사본) | 재빌드만 |

크기가 거의 같은 것(1.5KB 차)이 핵심이다 — Go 는 정적 링크라 **A 도 실행 시 의존이 없다.** 차이는 *빌드할 때* cli-maker 가 필요한가이지 *실행할 때*가 아니다.

**A + 얇은 façade** 로 정했다. `internal/` 은 그대로 두고 생성물이 실제로 부르는 것만 공개한다 → [ADR-0009](../../adr/0009-generated-cli-shape.md).

두 번째 갈림길은 "생성물을 얼마나 펼칠 것인가"였고, **펼쳐서**(명령마다 cobra 블록)를 골랐다. 얇게 두면 9d 의 golden test 가 자명해져 무의미해지고, ADR-0001 이 코드 생성을 열 이유로 든 "명령별 커스텀 로직"의 씨앗이 안 생긴다.

## 측정 — `go.mod` 한 줄이 프로그램을 바꿨다

`go 1.26` 을 `go 1.21` 로만 바꾸고 코드는 한 글자도 안 건드렸다:

| 명령 | `go 1.26` | `go 1.21` |
|---|---|---|
| `gh whoami` | `{"message":"Requires authentication",…}` exit **1** | `Encourage flow.` exit **0** |
| `gh zen` | `Approachable is better than simple.` | `Encourage flow.` |

`gh whoami` 가 젠 명언을 반환한다 — 모든 서브커맨드가 매니페스트의 마지막 명령을 실행한다. Go 1.22 의 루프 변수 변경이 **모듈마다 이 줄로 켜고 꺼지기** 때문이다([[go-modules]] · [[closures]]).

exit 0 에 그럴듯한 응답이라 아무도 눈치채지 못한다. 그래서 생성기가 뱉는 `go` 줄을 자동 추론이 아니라 **눈에 보이는 상수**로 두고 1.22 하한을 테스트로 지킨다.

## 자물쇠가 잠기는지 — 돌연변이 넷

"펼쳐서"를 고른 대가는 `internal/cli.Build` 와 `main.go.tmpl` 의 **중복**이다. 9d 가 그걸 봉인한다. 통과하는 테스트는 실패할 수 있어야 하므로 일부러 어긋내 봤다:

| 어긋낸 곳 | 결과 |
|---|---|
| 템플릿의 Short 형식 | FAIL `생성물 "GET: /plain", 런타임 "GET /plain"` |
| 템플릿에서 `MarkFlagRequired` 삭제 | FAIL (Required 불일치) |
| **런타임**(`build.go`)의 Short 형식 | FAIL `생성물 "GET /plain", 런타임 "GET @ /plain"` |
| 템플릿 첫 줄 표식 | FAIL (상수와 갈림) |

**양방향으로 잡힌다.**

## 인용 — 조용한 쪽이 더 위험했다

`Validate` 는 param 이름의 문자를 제한하지 않는다. 즉 `say"hi` 도 생성기까지 온다.

| 입력 | 날것 `"{{.}}"` | `{{printf "%q" .}}` |
|---|---|---|
| `say"hi` | 컴파일 안 됨 | `"say\"hi"` 값 보존 |
| `C:\temp` | **유효한 Go 인데 값이 바뀜** (`\t`=탭) | `"C:\\temp"` 값 보존 |
| `two⏎lines` | 리터럴 미종료 | `"two\nlines"` 값 보존 |

가운데 줄이 위험하다 — 깨지는 쪽은 즉시 발견되지만 이건 조용하다. 그래서 **유저 문자열은 예외 없이 `%q` 를 거친다**([[text-template]]).

## 대표 함정

- **잘못된 전제로 질문했다.** "`repo-name` 을 어디서 막을까"를 3지선다로 물었는데, *"param 이름이 Go 식별자 자리에 간다"* 는 전제 자체가 **내 데모 템플릿의 선택**이었다. 명령마다 익명 블록 `{ ... }` 을 쓰면 식별자를 만들 필요가 없어 문제가 사라진다. 막는 자리보다 **왜 막는가**가 먼저였다 — "Go 식별자가 아니라서"로 적었다면 backend 가 바뀌는 날 근거가 썩는다.
- **측정 장치가 네 번 틀렸다.** ① 파이썬 `re.sub` 이 치환 문자열의 `\t` 를 탭으로 바꿔 템플릿이 이상한 값을 낸 것처럼 보였다. ② `go run` 이 stderr 에 덧붙이는 `exit status 1` 을 프로그램 출력으로 착각해 "두 경로가 다르다"고 오판했다(컴파일된 바이너리끼리 재니 동일). ③ GitHub `/zen` 이 호출마다 다른 문구를 줘서 본문 비교가 무의미했다. ④ `awk` 로 템플릿을 깨뜨리려다 엉뚱한 곳을 지웠다. 전부 **값이 예상과 다르면 대상보다 측정 장치를 먼저 의심**해서 걸렸다.
- **`replace` 를 쓰면 internal 을 부를 수 있을 줄 알았다.** 로컬 소스를 직접 가리켜도 막힌다 — 규칙은 "받을 수 있느냐"가 아니라 "부를 수 있느냐"다([[internal-packages]]).
- **생성물의 `go.mod` 에 `require` 를 적으려 했다.** cli-maker 는 아직 배포 전이라 어떤 버전을 적어도 거짓이 된다(`git ls-remote … exit status 128`). `go mod tidy` 에 맡기니 두 줄이면 충분했다.

## 남긴 후속 과제

- **cli-maker 가 배포되지 않아 생성물이 그대로 빌드되지 않는다.** 지금은 `go mod edit -replace` 안내를 stderr 로 낸다. 태그를 붙여 공개하면 이 안내가 사라진다.
- **생성물의 빌드를 아무도 자동으로 확인하지 않는다.** 9d 는 소스를 파싱할 뿐 `go build` 를 돌리지 않는다. 느리고 네트워크를 타서 뺐다 — CI 가 생기면 그쪽 자리다.
- **`generate` 가 `-o`·`--timeout` 을 상속받는다.** 루트의 persistent flag 라 `--help` 에 보이는데 생성에는 아무 영향이 없다. 무해하지만 표면이 거짓말을 한다.
- **명령별 커스텀 로직은 여전히 표현할 수 없다.** A 는 ADR-0001 이 든 두 이유 중 *독립 배포 바이너리* 만 준다. 요구가 실제로 오면 템플릿을 두껍게 하는 방향(B)으로 얹는다.
- **`--help` 대조는 명령 목록만 같다.** 생성물은 루트라 `help`·`completion` 이 더 붙는다. 구조적 차이라 golden test 는 매니페스트에서 나온 명령만 본다.
- **M8 잔여** 중 `cli/load.go`·`manifest/load.go` 테스트는 그대로 남아 있다.
