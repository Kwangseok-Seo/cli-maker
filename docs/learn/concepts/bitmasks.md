# bitmasks

정수 하나에 여러 성질을 비트로 쟁여 놓고, `&` 로 한 칸씩 꺼내 본다. `os.FileMode` 가 그렇게 생겼다.

## 핵심

```go
fInfo.Mode()&os.ModeCharDevice != 0
```

`&` 는 **비트 AND** — 양쪽이 다 1 인 자리만 1 로 남긴다. 마스크에 1 이 한 칸뿐이면 결과는 "그 칸이 켜져 있었나"만 남으므로, `!= 0` 이 곧 **"이 성질이 있나?"** 가 된다.

## 실측 — stdout 이 무엇인지 가리기

```
마스크 os.ModeCharDevice     00000000 00100000 00000000 00000000
                                        ↑ 이 한 칸

콘솔        Dcrw-rw-rw-      00000100 00100000 00000001 10110110
            & 마스크          00000000 00100000 00000000 00000000  → 2097152 → true

파이프      prw-rw-rw-       00000010 00000000 00000001 10110110
            & 마스크          00000000 00000000 00000000 00000000  → 0 → false

리다이렉트  -rw-rw-rw-       00000000 00000000 00000001 10110110
            & 마스크          00000000 00000000 00000000 00000000  → 0 → false
```

- `os.FileMode` 는 그냥 `uint32`. `Dcrw-rw-rw-` 는 그 비트를 사람이 읽게 그린 문자열일 뿐이다(`D`=`ModeDevice`, `c`=`ModeCharDevice`, 뒤 9비트가 권한 `0666`).
- 파이프의 `p` 비트는 콘솔의 `D` 비트와 **다른 자리**다. 그래서 한 번의 AND 로 셋이 갈린다.
- 세우는 건 `|`: `os.ModeDevice | os.ModeCharDevice | 0666`.

## 헷갈리는 세 개의 `&`

```go
&buf                       // 주소 연산자 — 단항 ([[pointers]])
a && b                     // 논리 AND — bool 끼리
mode & os.ModeCharDevice   // 비트 AND — 이항
```

## 괄호가 필요 없다 (C 와 다름)

Go 에서 `&` 는 곱셈과 같은 우선순위, `!=` 는 그보다 낮다.

```go
fInfo.Mode()&os.ModeCharDevice != 0   // (Mode() & Mask) != 0 로 읽힌다
```

C 에서는 `&` 가 `!=` 보다 낮아 괄호가 필수인데 Go 는 그 함정을 없앴다. gofmt 가 `&` 주변 공백을 붙여 쓰는 것도 "얘가 더 세게 묶인다"를 눈으로 보이려는 것.

## 겪은 함정

- **stdout 이 터미널인지는 스스로 못 쟀다.** Claude Code 의 Bash 는 stdout 이 파이프(`prw-`), `!` 실행은 파일(`-rw-`)이라 둘 다 콘솔이 아니다. 사용자가 별도 터미널 창에서 돌려야 `Dcrw-` 가 나왔다. **측정 환경이 재려는 조건을 만족하는지부터 확인해야 한다** — 값이 예상과 다르면 대상보다 측정 장치를 먼저 의심한다.
- Windows 에서도 표준 라이브러리만으로 갈린다. `golang.org/x/term` 의존성은 필요 없었다.
